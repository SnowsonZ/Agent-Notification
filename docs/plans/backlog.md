# 待办清单

更新：2026-09-26。这里是本项目未关闭事项的唯一清单；[可验证交付方案](verifiable-delivery.md) §13 保留已完成事项的历史，未完成项指向这里。

## 使用规则

- **开工前先看这里**：Agent 接手工作（含中断后恢复）时先读本清单，再读 AGENTS.md 指向的规范；用户问「还有什么没做」时以本清单为准。
- **新增**：发现暂不处理的问题、用户提出但未排期的事、评审遗留的残余风险，都记成一行。编号 `B<序号>` 顺延，不复用；写清触发条件或日期、负责方、来源（缺陷编号、PR、讨论日期）。
- **开始做**：由它派生的任务书、PR 在「来源」里写上待办编号，例如「来源：待办 B5」。
- **关闭**：在完成它的**同一个 PR** 里，把这一行移到文末「已关闭」，写上日期和 PR 号。一个 PR 关闭了哪些待办、新增了哪些，写在 PR 描述的「待办」一栏。
- **不删除、不改写历史**：放弃的事项同样移到「已关闭」，写明「放弃」和原因（如用户决定不做）。
- **负责方为「用户」的事项**：Agent 不代做，只在合适时机提醒用户，并准备好用户操作所需的步骤。
- **定期核对**：评审方在每次收尾（交接、阶段结束）时核对本清单与实际状态，过期的触发条件或已经完成却没移走的行当场改正。

负责一栏：**用户**＝只能由用户做（授权、信任、账号、本机配置、真机验收、合并 R2 以上）；**评审方**＝Codex / Claude Code（判定器、护栏、评审）；**执行方**＝Zcode / OpenCode / Pi（产品代码与测试）。
